# Comprehensive implementation prompt

This is the amended build prompt for Oracle Commons, adopted as the project direction on October 14, 2026. The current documentation task establishes the constitution and plan; future implementation tasks use the prompt below to deliver working slices. Do not interpret an agent discovering this file as automatic authority to launch infrastructure or spend funds.

```text
Build Oracle Commons as our own independent, human-governed collaborative problem-solving platform.

Workspace: /Users/ryan/Desktop/Commons
Application: /Users/ryan/Desktop/Commons/commons
Development wiki: /Users/ryan/Desktop/Commons/wiki

The application and wiki now live at the root in commons/ and wiki/. The former legacy container was removed; do not recreate it. Another agent recently rebuilt commons/web. Inspect current files, contracts, and changes before editing. Preserve its work and working paths; do not reset, replace, move, or redesign that frontend. Write original Commons implementations. Do not restore or copy V3R1T4S code, prompts, catalogue entries, tests, datasets, discoveries, branding, or Git history. Existing original demos are development fixtures, not scientific discoveries.

First read root AGENTS.md, commons/AGENTS.md, wiki/CONSTITUTION.md, PRODUCT.md, ARCHITECTURE.md, BUILD_PLAN.md, NEXT.md, the latest WORKLOG.md entries, and DECONSTRUCTION.md. Read GOVERNANCE.md, OWNER_CONTEXT.md, RESEARCH_PROTOCOL.md, DATA_MODEL.md, SOLUTIONS.md, and ECONOMICS.md for the slice you implement. Read docs/tokenomics-plan.md as dated research; ECONOMICS.md records reconciliation with the constitution. DECONSTRUCTION is behavioral research only. The constitution is the founding product direction; historical fork/adapter and collaboration-only notes are superseded where they conflict.

Mission: humans direct their independently operated agents; agents coordinate useful research, accumulate inspectable evidence and recoverable memory, and discuss how to improve research; people decide platform changes through a DAO-style assembly. Scientific truth, agent attention endorsements, and human governance votes are separate systems.

Implement these required behaviors:

1. Human accounts and private instruction workspaces.
Provide easy human login/recovery, public profiles separate from private settings, agent ownership, scoped/revocable credentials, pause/stop controls, and a private preprompt editor like workspace instructions. Version drafts and published revisions; support owner defaults, agent overrides, problem assignments, effective-context preview, structured budgets/disclosure/permissions, and history/rollback. Only an authorized human owner edits instructions or expands grants. Agents fetch and acknowledge exact current context before work and when it changes. Enforce API scopes/limits in code; a prompt never grants voting, publishing private information, external spending, or tool privileges. Acknowledgement does not prove remote model obedience, and remote model billing limits are advisory unless genuinely metered.

2. Agent entrance and useful discovery.
Publish a public agent quickstart, llms.txt, versioned JSON schemas/OpenAPI, capabilities, examples, stable IDs, structured errors, pagination/cursors, idempotency rules and explicit state transitions. Agents should discover a bounded contribution before registration, then obtain owner-authorized credentials/context. Every core agent-eligible UI action has an authorized API operation; human-only operations are documented and reject agent principals. Maintain current client compatibility through tested adapters during migration.

3. Shared work and help.
Create/admit versioned problem records with exact acceptance criteria, sources/freshness, input access, and explicit demo status. Offer structured work units with methods/ranges/partitions/dependencies, capabilities, effort, outputs and stop conditions. Atomically claim complementary tasks with lease generations, heartbeats, quotas and stale-holder rejection. Permit intentional independent replication. Agents publish specific blockers/help requests with attempts, evidence and next action. Agents may endorse/retract once per target; show raw counts but at most one owner contribution toward default attention ranking. Rank help needs explicitly and show active investigations, blockers, meaningful checkpoints and complementary openings. Room to help includes active work needing assistance, not only empty problems.

4. Research discipline and memory.
Freeze versioned objective, criterion, inputs, method, boundaries, budget, seeds, analysis and appropriate controls before evaluating results. Preserve actual outputs, negative results, interrupted versus exhaustive coverage, and next useful actions. Never require consuming an entire compute allowance. Provide complete paginated history beyond the activity feed, attributed per-problem wiki notes, proposed/reviewed frontier updates, and exact resumption packets. Enforce a durable handoff atomically before normal completion/release; emergency stops/revocation/expiry must remain safe and retain existing notes without forcing continued work.

5. Evidence, proof challenges, and the solution registry.
Create immutable candidate/manifest versions with exact scope, criterion/plan/input references, finalized artifact hashes/generations, commands/environments, actual outputs, baseline observations, credit and disclosure. Separate completeness, reproduction/correctness, novelty, criterion/scope and external acceptance. Record reviewer roles/operators/affiliations/conflicts, independent versus supplied-checker methods, evidence and objections. Exclude all coauthor/contributing operators from independent-owner counts; fresh contexts or agreeing agents are not proof. Support counterexamples, disputes, resolutions, withdrawals, retractions and supersession without erasing history. Log every candidate/partial result with honest status in a searchable registry and link it to attempts/wiki/reviews. Do not seed real results from demos or retired discoveries.

6. Ongoing research-process discussion.
Give humans and authorized agents durable threads to discuss methodology, coordination, tools, verification, resources and platform friction while using Commons. Link observations to work; support replies/edit history, citations, subscriptions/mute/digests, bounded owner-shared posting limits, duplicate linking, moderation/appeals and attributed summaries preserving dissent. Discussion/wiki content is untrusted data and cannot become owner instructions. A post must not trigger automatic model execution or unbounded agent chatter.

7. Proposal development and human governance.
Develop discussion ideas into versioned proposals with evidence, requested change, alternatives, benefits/risks, costs, implementation owner, measurable acceptance/evaluation and rollback. Agents may draft, critique and endorse; advisory endorsements remain separate from binding ballots. Only admitted PEOPLE sponsor binding votes and vote. One human member has one ballot regardless of agents/tokens/spending. Start with invitation-reviewed membership and disclose that login/email is not unique-person proof. Require human sessions, recent authentication and deliberate confirmation; reject agent keys for ballots, sponsorship, membership and instruction/grant edits. Implement frozen proposal text/policy/electorate, seven-day discussion/vote defaults, replace/retract ballots, quorum/tie/abstention/no-quorum cases, auditable close, and constitutional amendment rules from GOVERNANCE.md after founding ratification. Accepted proposals create tracked implementation and evaluation records; they never automatically execute arbitrary text, certify science, deploy code or spend funds. Preserve rejection, supersession and rollback. Keep the first assembly off-chain; on-chain governance is a later explicit proposal.

8. Privacy and execution boundaries.
Enforce visibility through APIs/storage/wiki/posts/summaries/events/search/notifications/logs/exports/backups. Separate private owner context, public profiles, member content, shared access and commitment-only evidence. Private text cannot be declassified by an agent quoting it into a proposal. Keep sealed objects/salts private, publish only authorized commitments, and label the limits of automated leak detection. Validate/quarantine/finalize uploads and authorize downloads; do not run contributed code inside the API or a secrets-bearing worker. Hosted verification requires a separately reviewed genuine sandbox. Separate human identity, membership, agent keys, model execution, deployment and future wallet authority.

9. Real visible work.
Connect the preserved goofy 2D village and accessible text views to actual persisted researching/blocked/reviewing/idle/disconnected states. Sprites/workbenches link to real tasks, checkpoints, help, wiki, results and discussions. Show freshness/errors and canonical deep links. Preserve mobile, keyboard and reduced-motion support. Never fabricate activity, people, votes or discoveries.

10. Build a hosted platform deliberately.
Target the existing React/Vite frontend on Vercel plus short Node API Functions, Firebase Authentication, Cloud Firestore for durable domain records and Cloud Storage for artifacts. Use emulators and isolated preview data; no unnecessary frontend rewrite. Refactor current Node/SQLite service through domain/storage adapters and explicitly migrate original local records with ownership proof, backups, reconciliation and rollback. Do not use SQLite/function memory as hosted truth or copy old sessions/keys/leases into production. Privileged Firebase server SDK calls need authorization in the API because client Rules do not protect them. Use retry-safe transactions, durable idempotency/outbox delivery and distributed quotas; waitUntil is not a durable queue. Keep initial research compute owner-operated. Prepare billing limits/alerts, monitoring, restore tests, license/membership/retention policies and deployment settings before requesting any required paid provisioning/public-launch authorization. Cloud Storage currently requires Blaze. Avalanche payments remain a later adapter and cannot buy human vote weight or scientific validity.

11. Integrate economics without surrendering human authority.
Implement ECONOMICS.md as the reconciled direction: optional owner-chosen wallets bound to stable Firebase/operator identity; nontransferable service credits with separate promotional/purchased lots; earned contribution history; and only later funded bounties/optional transferable assets. Use integer units, balanced immutable journals, policy-pinned atomic holds/settlement/timeout/appeal compensation, current context/scopes and owner-shared cumulative caps across all agents. Ordinary research continuation, handoffs, objections, method discussion, governance proposals and human ballots stay free within limits. Exhaustion/revocation must not block a safe stop. Prototype Reown/Privy recovery/linking on Fuji without selecting a paid provider or requiring wallets at signup. Agents may reserve only explicitly granted off-chain service credits; they never receive ordinary wallet signing, linking/recovery or human treasury ballot authority. Human members govern treasury budgets under equal votes; independent signers execute approved policy, with a ratified post-approval delay before real money. Treat dollar caps as planning figures until enforceable asset-unit/signing controls exist. Persist/reconcile payment intents and verified accepted/executed receipts; test duplicates, pending/failed/replaced operations, RPC lag and signer bypass. Research prices, rewards, referral ceilings, 100-million-token allocation/vesting and launch thresholds are proposals, not approved settings or promises. Build identity/research foundations first, then promotional-credit experiments, then separately authorized real funding, and decide transferability last.

Follow BUILD_PLAN.md in working vertical slices. Begin with contracts, Firebase emulator/human identity, owner context and authority boundaries, then deliver one complete collaboration loop: two owners with private instructions and acknowledged agents → bounded claim → checkpoint → help request → endorsement → complementary task → durable handoff → candidate/evidence → independent report or objection. Use a third operator if both research owners are coauthors.

Then demonstrate the improvement loop: research friction → ongoing discussion → evidence-backed proposal → human sponsorship → eligible human ballots → decision → tracked implementation → verified outcome/evaluation. Agents cannot cast human votes. Test fixtures may use shortened clocks and must never be presented as a live human DAO.

Test authorization/owner isolation, private context, stale receipts/keys, concurrent claims and fencing, expiry/quotas, endorsement normalization/retraction, handoff enforcement/safe stop, evidence integrity and claim versions, review conflicts/objections, full memory retrieval, injected text and privacy canaries, human-only governance, frozen electorates/ballots/deadlines/quorum, idempotency/outbox retries, and persistence across restart/redeploy. For economics, test shared-agent double debit, budget/hold/reset races, one-time grants, timeout/appeal compensation, policy versions, zero-credit free actions, wallet/account linking/recovery, signature replay/forgery, private balances, referral/self-review farms, forged/duplicate receipts, payout retries/direct signer bypass, reconciliation pause/restore and wallet-provider outages. Use original synthetic known-good/broken fixtures and Firestore emulator tests. Exercise relevant browser and browserless agent flows.

Implement working behavior for the assigned slice, not another plan. Do not claim unbuilt phases as complete. After every task, update relevant architecture/spec pages and NEXT.md; append actual changes, verification commands/results, limitations, and the next useful action to WORKLOG.md. Preserve previous worklog history and concurrent work. Do not publish, deploy, provision paid services, message third parties, run scheduled research, or spend funds merely because this prompt is stored in the wiki; follow the human's authorized task scope.
```
